# Actividad: Propuesta de Práctica Temática Pequeña para GitHub Classroom

## Descripción general
En esta actividad vas a diseñar una **propuesta de práctica temática pequeña** enfocada en arquitectura de computadoras y programación de sistemas. La prioridad es que documentes una idea clara, viable y bien justificada antes de escribir código.

Tu propuesta puede implementarse (de forma opcional y mínima) usando uno de los lenguajes permitidos.

## Objetivo de aprendizaje
Al finalizar esta actividad, serás capaz de:
- Definir un problema concreto y acotado para una práctica técnica.
- Justificar la elección de lenguaje según el caso de uso.
- Diseñar la estructura base de un repositorio profesional y ordenado.
- Documentar casos de uso, alcance, pruebas y criterios de éxito.
- Construir (si el tiempo lo permite) un prototipo mínimo alineado a la documentación.

## Lenguajes permitidos
- ARM64 Assembly
- C
- Python
- Bash

## Reglas para mantener el proyecto pequeño
1. Debe resolver **una sola necesidad principal**.
2. Debe ejecutarse en terminal (sin interfaz gráfica compleja).
3. Evita integraciones externas, servicios en nube y APIs.
4. Evita dependencias pesadas y configuraciones largas.
5. El prototipo (si lo haces) debe ser corto, legible y funcional.
6. Si eliges ARM64 Assembly, limita el alcance a programas muy pequeños.

## Entregables esperados
1. `docs/propuesta.md` completo.
2. `docs/caso_de_uso.md` completo.
3. `docs/estructura_repositorio.md` revisado y adaptado al proyecto.
4. `docs/plan_de_pruebas.md` con casos de prueba mínimos.
5. `tests/test_plan.md` con checklist final.
6. `src/main.<ext>` como placeholder o prototipo básico.
7. Ajustes en `scripts/run.sh` para ejecutar tu versión.

## Instrucciones para el estudiante
1. Lee todo el repositorio antes de editar.
2. Completa primero `docs/propuesta.md`.
3. Después completa `docs/caso_de_uso.md`.
4. Revisa la estructura en `docs/estructura_repositorio.md`.
5. Define pruebas mínimas en `docs/plan_de_pruebas.md` y `tests/test_plan.md`.
6. Solo al final, si te alcanza el tiempo, implementa un prototipo pequeño.
7. Mantén commits claros y frecuentes con mensajes descriptivos.

## Ejemplos de posibles temas
- Mini Toolkit en ARM64
- Asistente de Estudio en Terminal
- Reporteador de Información del Sistema
- Organizador de Archivos
- Juego de Aprendizaje en Línea de Comandos

## Criterios generales de evaluación
- Claridad del problema y del objetivo.
- Coherencia entre necesidad, solución y alcance.
- Viabilidad técnica para un proyecto pequeño.
- Calidad y orden de la documentación.
- Estructura limpia del repositorio.
- Calidad del plan de pruebas.
- (Opcional) Prototipo mínimo funcionando.

## Nota importante
Primero se evalúa la **documentación, planeación y justificación**. Después, de forma opcional, se puede implementar un prototipo pequeño para demostrar la idea.
